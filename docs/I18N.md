## 概述

SFTP+ 使用自建轻量 i18n（不依赖 Angular i18n / ngx-translate）。`SftpI18nService` 在构建期通过 webpack `asset/source` 内联 `locale/*.po`，运行时 `i18n.t(key)` 查表。

**翻译源文件是 `locale/*.po`，不是 `sftp-i18n.service.ts` 里的硬编码字典。**

## 支持的语言

| 语言代码 | 语言 | 状态 |
|---------|------|------|
| `zh-CN` | 简体中文 | 完整（与功能同步） |
| `en-US` | English | 完整（与功能同步） |
| `zh-TW` / `en-GB` / `ja-JP` / `ko-KR` / `fr-FR` / `de-DE` / `es-ES` / `pt-BR` / `pt-PT` / `ru-RU` / `it-IT` / `id-ID` / `cs-CZ` / `da-DK` / `hr-HR` / `pl-PL` / `sv-SE` / `tr-TR` / `bg-BG` / `sr-Latn` / `uk-UA` / `af-ZA` | 其余 22 种 | 有词条；缺失或空 msgstr 回退 `en-US` |

完整 `Locale` 联合类型见 `src/services/sftp-i18n.service.ts`。

## 语言检测策略

```
优先级 1 (最高)  →  用户手动选择（config.yaml: tabby-sftp-plus.lang）
优先级 2        →  旧版 localStorage: sftp-plus-locale / sftp-plus-settings.lang
优先级 3        →  Tabby ConfigService 语言
优先级 4        →  navigator.languages
优先级 5        →  navigator.language
优先级 6 (最低)  →  默认 zh-CN
```

## 翻译键

键采用点号命名空间：`<分组>.<键名>`（如 `settings.conflictDigest`、`file.symlink`）。

完整键表以 `locale/zh-CN.po` / `locale/en-US.po` 为准，本文不再维护一份会过期的清单。

v2.3.0 新增分组示例：

| 前缀 | 用途 |
|------|------|
| `settings.editableExtensions*` / `settings.allowViewEditAllFiles*` | 可编辑扩展名与「允许全部类型」 |
| `settings.conflictDigest*` | 冲突内容摘要 |
| `file.symlink` / `file.shortcut` | 符号链接 / 快捷方式角标 |

## 使用方法

```typescript
this.i18n.t('pane.local')
this.i18n.t('pane.nItems', { count: items.length })
```

模板：

```html
<span>{{ i18n.t('pane.local') }}</span>
```

翻译字符串里用 `{key}` 占位，由 `i18n.t` 替换。不要在代码里拼接多语言句子。

## 新增翻译

1. 在 `locale/zh-CN.po` 和 `locale/en-US.po` 追加相同 `msgid`，并写好 `msgstr`
2. 同步到其余 `locale/*.po`（可先空 msgstr；运行时回退英文）
3. **不要**再往 `sftp-i18n.service.ts` 里加 TRANSLATIONS 对象（该表已删除）
4. 新增一种语言时：加 `.po`、在 `sftp-i18n.service.ts` 的 `Locale` 与 `require()` 列表中注册、设置页语言下拉增加选项

`.po` 示例：

```
msgid "settings.conflictDigest"
msgstr "冲突时计算内容摘要"
```

仓库里的 `scripts/add-*-i18n.mjs`、`scripts/fill-missing-i18n.mjs` 是历史维护脚本，一次性日期脚本不要提交进发布包。

## 回退机制

```
目标语言 msgstr 非空 → 使用
否则 en-US → 使用
否则返回键名本身
```

## 最佳实践

1. 用户可见字符串一律 `i18n.t()`
2. 用 `{placeholder}`，不要拼接
3. 同一含义共用一个 msgid
4. UI 要能适应中英长度差异
5. 发布前至少保证 zh-CN / en-US 与功能同步
